# PHASE 0~4·5A 검증 기록 — 0.5.0

검증일: 2026-11-03, 한국 시간. Windows 11 build 26200, Python 3.12.14, PySide6 6.12.0, pytest 9.2.0, ruff 0.17.3, PyInstaller 6.22.3.

## 자동 회귀

**215개 통과**: 기존 148개 + 채팅/저장 회귀 63개 + 채팅 Qt UI 4개. 새 임시 DB와 Qt offscreen 플랫폼으로 실행했습니다. 실제 사용자 DB는 사용하지 않았습니다. `ruff check --no-cache .`, `ruff format --check --no-cache .` 통과.

- 기존 설정·저장·계획/반복/알림·캐릭터·집중/통계·생활/브리핑·프로세스 종료 검사를 유지했습니다. 0.4.1의 기존 오류 6건은 [감사 보고서](AUDIT_REPORT_0.4.1.md)에 있습니다.
- 한국어 24개 명령 형태와 모호한/잘못된 날짜·시각·범위·일괄 명령 16개를 검사했습니다. 모호한 문장을 실제 변경으로 연결하지 않습니다.
- 할 일/일정 선택·동명 대상·추가/취소·완료/취소·날짜 이동·삭제·반복 범위·자정 일정·명시적 마감 보존.
- 확인 중복 1회 처리, 변경/삭제된 대상·만료·새 명령/대화/보관 변경으로 오래된 카드 거부.
- 진행 타이머 보호와 시작/일시정지/재개/확인 후 중지, 실제 공부 합계와 기존 캐릭터/타이머 UI 동기화.
- 명령 처리 정보 저장 실패·성공 대화 저장 실패·지연 FK로 실제 commit 실패를 각각 주입했습니다. 계획·타이머 DB·런타임·세션/구간 ID·성공 대화·신호 모두 롤백했습니다.
- 기존 실행 중 타이머의 일시정지/중지/초기화 실패 뒤 원상 복구, 같은 카드 재시도와 구간 시간 중복 적립 방지.
- 중첩 실패를 내부에서 잡아도 부분 커밋 금지, 바깥 커밋 뒤 신호 발행.
- 50개씩 대화 조회·재생성 서비스에서 기록 조회와 카드 복원 금지·보관 off·재활성화 시 소급 저장 없음·대화 삭제와 계획 분리.
- 키 형태 canary를 DB에 쓰기 전에 거부, HTML/SQL 문자열을 일반 제목으로 보관하고 실행하지 않음. 네트워크 연결 진입점을 실패하게 한 상태에서도 로컬 명령 동작.
- 스키마 1/2/3/4 이전과 backup DB 원래 버전·데이터 보존 검사. 새 스키마는 5입니다.

키 형태 탐지는 모든 비밀 문자열을 찾는 보장이 아닙니다. 가짜 시계·주입 오류·전원 이벤트 검사는 실제 OS 시계나 전원 상태를 변경하지 않습니다.

## Windows Qt 자체 실행

`tools/native_smoke.py`를 `QT_QPA_PLATFORM=windows`로 실행했습니다. 전용 `.qa/native-smoke-phase5a/<UUID>` DB를 사용하고 `.qa/native-smoke-phase5a.json`에 결과를 저장했습니다.

- 기존 펫 최초 표시·트레이 Qt 표시 상태·관리창 닫기·크기/숨김 복원·계획 입력/완료·월/주/일·집중/통계·브리핑·집중 크기 복원 확인.
- 채팅 입력/보내기 버튼으로 미리보기 전 비저장, 확인 후 실제 할 일 저장, 채팅의 타이머 시작/일시정지/재개 확인.
- 진행 중 전체 종료 후 paused 체크포인트, 설정 보존, 실행 잠금 해제, 집중/생활/브리핑/알림 타이머 정지 확인.

Qt API로 앱을 조작한 검사입니다. 실제 OS 마우스/키보드·트레이·알림 클릭을 대신하지 않습니다.

## 앱 위젯 렌더링

`tools/render_preview.py`의 전용 `.qa/preview-data-phase5a/<UUID>` DB로 화면을 만들었습니다. 홈/계획/캘린더/집중/통계/생활/설정과 채팅 밝은/어두운 화면을 확인했습니다. 720×560에서 메뉴가 스크롤되고, 확인 내용·입력·버튼이 보입니다. 대화는 KST로 표시하며 HTML을 해석하지 않습니다. 실제 사용자 데이터나 다른 앱을 캡처하지 않았습니다.

## EXE 빌드

PyInstaller 0.5.0 one-folder 빌드를 완료했습니다. 버전 리소스·기본 모루 64 PNG·아이콘·Qt Windows 플러그인·tzdata Asia/Seoul을 포함하며 `assets/characters` 사용자 원본, DB·로그·QA·키 파일은 제외했습니다.

EXE의 실제 실행은 이번에도 미검증입니다. 이전 Windows 앱 제어 정책 거부를 우회하지 않았으며 깨끗한 PC에서의 확인은 별도입니다. 검증된 실행 경로는 `run_windows.bat`의 Python/PySide6 소스 실행입니다.
