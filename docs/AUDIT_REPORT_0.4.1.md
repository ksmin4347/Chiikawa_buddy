# 0.4.1 기능 감사 결과

점검일: 2026-10-30 (한국 시간). 대상은 승인·구현된 PHASE 0~4입니다. 실제 사용자 DB와 캐릭터 원본 27개는 변경하거나 업로드하지 않았습니다.

## 결론

기존 자동 테스트 138개는 모두 통과했지만, 추가한 재현 검사에서 아래 6건의 오류를 확인했습니다. 모두 수정했으며 재현 검사와 관련 보호 검사 10개를 회귀 테스트에 포함했습니다. 최종 전체 148개와 품질 검사, Windows Qt 자체 검사, 0.4.1 폴더형 빌드 결과를 확인했습니다.

## 확인하지 못한 것

Windows 실제 입력 검사를 위해 임시 DB 전용 `tools/manual_audit.py`를 실행했습니다. 제한된 실행 환경에서는 창이 도구에 노출되지 않았고, 일반 데스크톱으로 옮긴 뒤에는 창을 찾았으나 Computer Use의 앱 접근 승인이 시간 초과되었습니다. 따라서 실제 클릭/드래그/트레이 입력을 확인했다고 보고하지 않습니다. 감사 앱은 정리했습니다. 이는 자동 승인 심사에서 코드나 수정 작업이 거부된 것은 아닙니다.

OS 알림 토스트, 실기기 절전/복귀·시계 변경·전체 화면 게임/발표·DPI/모니터 교체·Windows 10·장시간/대규모 자료·깨끗한 PC에서 EXE 실행은 수동 검증이 남았습니다. 이전 EXE의 Windows 앱 제어 차단을 우회하거나 OS 설정을 바꾸지 않았습니다.

Windows 전체 화면 감지는 공식 알림 상태 휴리스틱이며 모든 앱을 감지하지 않습니다. 앱이 꺼져 있던 동안의 시계 전진과 정상 시간 경과는 완전히 구분할 수 없습니다. 강제 종료는 마지막 약 5초 진행이 유실될 수 있습니다.

## 확인 방법

소스 실행은 `run_windows.bat`입니다. 캐릭터를 더블클릭하고 계획·집중 타이머·공부 통계·생활·브리핑을 확인합니다. 사용자 DB에 예시 자료를 만들지 않고 실제 입력을 점검하려면 `.venv\Scripts\python.exe tools\manual_audit.py`를 실행합니다. 새 QA 데이터만 사용하고, 종료 메뉴 또는 20분 안전 종료로 정리합니다.

상세 수동 항목은 `docs/MANUAL_TESTS.md`에 유지합니다. 이번 작업은 PHASE 0~4 안정화이며 PHASE 5를 시작하지 않았습니다.
