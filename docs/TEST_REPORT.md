# PHASE 0·1·2 검증 기록 — 0.2.0

검증일: 2026-10-28, 한국 시간. Windows 11 build 26200, Python 3.12.14, PySide6 6.12.0, python-dateutil 2.9.0.post0, tzdata 2026.5, pytest 9.2.0, ruff 0.17.3, PyInstaller 6.22.3.

## 자동 회귀

**79개 통과.** 기존 PHASE 0·1 검사 34개와 PHASE 2 및 종료 회귀 검사를 포함합니다. 테스트 전용 새 임시 경로와 Qt offscreen 플랫폼을 사용했습니다.

- 설정 보존, 잘못된 타입·손상 DB·상위 스키마 보호, 기본 에셋 대체, 좌표 보정, 클릭·더블클릭·드래그 분리, 숨김 애니메이션 중단.
- 스키마 1→2 이전에서 설정 보존과 원본 백업. 이전 중 DDL 오류를 주입했을 때 전체 롤백.
- 할 일 생성·수정·날짜 이동·완료/취소·삭제, 카테고리 변경·삭제 시 항목 유지.
- 반복 요일·간격·횟수·월말·윤년, 이번만 수정/삭제, 다른 달로 이동, 이후 분할 시 남은 횟수·개별 예외·완료 이력 보존.
- 반복 중단 시 개별 수정·완료 이력을 일회성 항목으로 보존. 이후 수정 중 새 항목 저장 실패 시 분할 전체 롤백.
- 종일의 종료 날짜 배타 처리, 자정을 넘긴 일정의 양쪽 날짜 표시.
- DST의 존재하지 않는 시각을 건너뛰고 COUNT에 포함하지 않음. 먼 미래 조회에서도 반복 간격 위상 유지.
- DB를 닫고 다시 연 뒤 할 일·일정·분류·개별 예외·날짜별 완료 상태 보존.
- 알림 정시/사전 시각·개별 변경 마감, 완료/취소 제외, 알림 처리 이력에 따른 중복 억제, 시계 역행·복귀 후 오래된 알림 제외.
- 방해 금지의 자정 넘김, 일시중지와 재개 시 과거 알림 비누적, DB 오류 시 알림 서비스 장애 격리.
- 항목 ID 재사용 방지, 반복 분할 후 동일 알림을 다시 보내지 않도록 처리 이력 복사.
- 실제 월간 6×7 칸, 기간 이동·주 시작 변경, 주/일 시간표와 겹침 배치, 짧은 인접 일정 비겹침.
- 빠른 추가와 체크 완료 시 계획/캘린더 동시 갱신, 이전 미완료 표시, 삭제 취소 보존, 입력/저장 실패 시 편집 내용 보존.
- 자식 프로세스로 중복 실행 활성화 및 **관리창을 연 상태에서 종료 메뉴 신호로 프로세스 종료** 확인.

`ruff check`와 `ruff format --check`도 통과했습니다. Qt offscreen 테스트는 실제 OS 마우스 입력·합성·트레이 클릭·토스트 수신을 뜻하지 않습니다.

## Windows 네이티브 Qt 자체 검증

`tools/native_smoke.py`는 실제 Windows Qt 플랫폼에서 별도 `.qa/native-smoke-phase2` DB로 실행했습니다. `.qa/native-smoke-phase2.json`에 다음 결과를 기록했습니다.

- 최초에는 펫만 표시, 트레이 Qt 표시 상태 true.
- 관리창을 닫아도 펫 유지, 크기 즉시 반영, 숨김/복원 시 애니메이션 중단/재개.
- 오늘의 계획 입력창으로 추가하고 체크하여 완료 처리.
- 월간 화면 렌더링과 주간 7일/일간 1일 전환.
- 관리창이 열린 상태에서 전체 종료, DB 설정 재조회, 실행 잠금 해제, 알림 타이머 중단.

이 검증 중 관리창의 닫기 이벤트가 전체 종료를 막는 문제를 발견했습니다. 일반 창 닫기와 명시적 전체 종료 경로를 구분하고 회귀 테스트를 추가했습니다. Qt API 자체 검증이며 OS 입력 주입을 통한 수동 조작 확인과는 구분합니다.

## 시각 확인

전용 QA 예시로 홈·오늘의 계획·월/주/일 캘린더·설정·어두운 테마를 앱 위젯에서 렌더링했습니다. 한글·카드·선택 날짜·완료 표시·겹치는 일정의 별도 열·스크롤 시 고정 종일 영역을 확인했습니다. 예시 데이터는 실제 사용자 DB에 넣지 않습니다. 전체 바탕화면이나 다른 앱의 화면은 저장하지 않았습니다.
