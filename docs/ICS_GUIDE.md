# ICS 파일 교환 — 0.7.0

**캘린더 → ICS 파일 교환** 또는 **설정 → ICS 파일 교환**에서 사용합니다. API 키나 계정 연결 없이, 직접 선택한 `.ics` 파일을 읽거나 저장합니다. 자동 동기화·구독·Planit 계정 연결은 제공하지 않습니다.

## 가져오기

1. 가져올 기간을 정합니다. 마지막 날짜를 포함하며 1~366일, 1900~2100년 범위입니다.
2. **출처 이름**을 정합니다. 같은 캘린더를 다시 가져올 때는 같은 이름을 사용하세요. 파일 이름을 바꿔도 출처 이름과 파일 안의 UID로 구분합니다.
3. **ICS 파일 선택**을 누릅니다. 미리보기만으로는 계획을 저장하지 않습니다.
4. 행을 선택해 파일 내용·현재 앱 내용·외부 UID·원래 발생일·제외 사유를 확인합니다. 가로/세로 스크롤과 읽기 전용 상세 복사를 사용할 수 있습니다.
5. 체크한 뒤 **선택 항목 가져오기**를 누릅니다. 추가/갱신 개수를 확인하고 최종 질문에 동의해야 저장합니다.

새 항목만 기본 체크합니다. 같은 내용은 선택할 수 없고, 시간 겹침·원본 갱신·앱 수정과의 충돌·앱에서 삭제한 항목 재추가는 기본 체크하지 않습니다. 갱신은 제목·메모·시각·할 일 완료/우선순위를 파일 내용으로 바꾸며 기존 앱 카테고리·알림은 보존합니다. 반복으로 바꾼 연결 항목이나 기존 알림을 유지할 수 없는 변경은 덮어쓰지 않습니다.

미리보기는 5분 후 만료합니다. 기간/출처 또는 계획이 바뀌면 다시 미리 보기해야 합니다. 선택한 항목 전체를 한 트랜잭션으로 저장하며 실패하면 이번 가져오기를 되돌립니다. 파일에서 사라졌거나 취소된 항목도 이미 앱에 저장했다면 자동 삭제하지 않습니다.

## 내보내기

1. 기간과 **일정만 / 할 일만 / 할 일과 일정**을 고릅니다.
2. **내보내기 미리보기**를 누르고 포함할 항목을 체크합니다. 제외 개수와 상세 이유도 확인하세요.
3. **선택 항목 ICS 저장**에서 위치를 정하고 최종 확인합니다. 기존 파일이 있으면 교체합니다. 저장 중 대상이 바뀌거나 실패하면 기존 파일을 유지합니다.

제목·메모·날짜/시각·할 일 완료 상태와 우선순위를 내보냅니다. 반복 규칙·분류·앱 알림·공부 기록·대화·API 키는 넣지 않습니다. 내보낸 파일 자체에 개인 일정과 메모가 들어가므로 공유 전 내용을 확인하세요.

시작 시각 없이 마감 시각만 있는 할 일은 표준의 시작/마감 타입을 맞추기 위해 **예정 날짜 00:00 시작 + 원래 마감 시각**으로 기록합니다. 다른 앱에는 자정 시작으로 보일 수 있습니다. 먼작귀는 보조 속성으로 원래의 '시작 시각 없음'을 복원합니다. 마감이 시작보다 이전/동일한 기존 할 일은 제외 사유를 표시하며 앱 데이터는 바꾸지 않습니다. [RFC 5545의 VTODO](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.6.2).

## 지원 범위

| 항목 | 현재 지원과 한계 |
|---|---|
| 파일 | UTF-8/BOM `.ics`, 8 MiB 이하, VEVENT/VTODO 구성 요소와 펼친 결과 각각 최대 1,000개 |
| 일정 | 제목·메모·시작/끝, 종일·자정 넘김. 시각 있는 일정은 양수 길이가 필요하며 최대 366일 |
| 할 일 | DTSTART가 있는 항목, 선택적 시각 마감·완료·3단계 우선순위. DUE만 있는 항목/날짜만 있는 DUE는 제외 |
| 반복 | DAILY/WEEKLY/MONTHLY/YEARLY의 제한된 규칙, 요일/간격/종료·횟수, EXDATE와 개별 수정/취소. 선택 기간의 **독립 항목**으로 교환 |
| 제한된 반복 | 순번 요일(둘째 월요일 등), RDATE/EXRULE, RECURRENCE-ID RANGE 등은 제외 사유 표시. 원래 반복 규칙은 파일로 왕복 보존하지 않음 |
| 시간대 | UTC·내장 IANA 시간대, Korea Standard Time. 시각은 서울로 변환하고 종일 날짜는 유지. 시간대 없는 값은 파일 기본 시간대 또는 서울 |
| 시간대 한계 | 사용자 정의 VTIMEZONE은 평가하지 않음. 알 수 없는 TZID·존재하지 않는 시각·모호한 일광절약 시각은 안내 후 제외. 필요하면 원본 앱에서 UTC로 내보내기 |
| 부가 정보 | 첨부·URL·초대·알람·분류 등은 실행/검색/가져오기 하지 않음. 회의 요청·취소 메시지는 거부 |

종일 일정의 ICS 종료 날짜는 포함하지 않는 끝 날짜입니다. 화면의 포함 종료 날짜와 변환하므로 하루씩 줄여 입력할 필요가 없습니다. [RFC 5545의 VEVENT](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.6.1). 파싱은 [icalendar](https://icalendar.readthedocs.io/en/stable/reference/api/icalendar.cal.html)를 사용하며 위의 제한된 범위만 앱에 반영합니다.

각 일정의 UID와 반복 발생일이 재가져오기 식별 기준입니다. 원본 앱이 UID를 바꾸면 새 항목으로 판단할 수 있습니다. 내용 중복도 검사하지만 다른 제목/시간으로 바뀐 별도 UID를 같은 일정으로 추측하지는 않습니다. 다른 앱의 VTODO 지원 수준도 다르며 실제 Google/Outlook/Planit 파일 상호 운용은 수동 확인이 남아 있습니다.

## 업데이트와 오류

기존 실행을 트레이에서 종료하고 먼작귀 바로가기 또는 `run_windows.bat`으로 다시 실행합니다. 개발 환경을 갱신할 때는 `setup_windows.bat`으로 새 의존성을 설치합니다. 사용자 데이터 위치는 `%LOCALAPPDATA%\DesktopBuddy` 그대로입니다. 스키마 6→7 이전 전 SQLite backup API로 백업하고 기존 계획·타이머·캐릭터·대화를 보존합니다.

파일 작업은 취소하거나 창을 닫을 수 있습니다. 이미 저장이 끝난 파일을 취소로 되돌리지는 않습니다. 큰 파일/권한 오류/지원하지 않는 형식은 안내를 확인하고 원본 앱에서 기간을 줄이거나 UTC ICS로 다시 내보내세요. JSON 백업 파일이나 앱 DB를 ICS 입력으로 사용하지 않습니다.
