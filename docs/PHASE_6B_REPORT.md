# PHASE 6B 검토 — 0.6.1

2026-11-10 후속 개발 요청에 따라 연결 테스트와 선택형 온라인 텍스트 대화를 구현했습니다. 6C AI 작업 제안·실행은 포함하지 않습니다. 실제 사용자 키/DB를 테스트에 사용하지 않았고 실제 API 요청·청구도 발생시키지 않았습니다.

## 구현과 경계

- `ai/config.py`, `client.py`, `http_transport.py`: 공식 OpenAI SDK 3.49.0 / httpx2 2.16.0의 Responses API. 고정 `https://api.openai.com/v1/responses` POST만 허용, TLS 검증·환경 프록시 무시·리다이렉트/SDK 및 HTTP 재시도 금지. 응답 1 MiB, 표시 본문 16,000자, 최대 출력 2,048토큰(테스트 128), 비동기 응답 대기 60초 제한.
- `ai/job.py`, `services/online_service.py`: 한 요청/전용 daemon 스레드, 시작 시 SDK/키 조회 없음. 작업 중 키를 읽어 입력/출력의 실제 키·비밀 패턴을 검사하고 원시 예외/키를 Qt 신호나 로그에 넣지 않음. 사용자 문장 저장은 검사 뒤 GUI 승인으로 수행하며 저장 실패 시 요청하지 않음.
- GUI의 기존 SQLite 연결은 작업 스레드에서 사용하지 않음. 취소/화면·대화·캐릭터·키·모델 전환/종료 뒤 결과 무효화. 스레드 강제 종료나 GUI join 대기 없음. 이미 전송된 요청/요금 취소는 보장하지 않음.
- `ChatService`/기존 스키마 6의 mode/화자 필드 사용. AI 응답은 일반 텍스트이며 실행기에 연결하지 않음. 과거 대화/계획/공부/파일/포인터 자동 전송 없음. 현재 문장/고정 캐릭터 지침만 전송, `store=false`, 도구/백그라운드/스트리밍 없음.
- `characters/ai_persona.py`: 캐릭터별 성격 지침과 우사기 외곽 형식. 코드/경로/날짜 전역 치환 없음. 이전 대화/당시 화자 보존. 실제 모델의 말투/정확성 인수는 별도.
- `ApiKeyDialog`/`ChatPage`: 비용/전송 안내·명시적 테스트·선택형 모드·요청 취소·반환 토큰 안내. 테스트 성공 후 직접 켜고 재실행 시 오프라인. 키/모델 변경 시 다시 테스트. 입력 중 미저장 키로 테스트하지 않음. 토큰 누락은 확인 불가이며 요금 추정 없음.

기본 모델 `gpt-5.6-terra`는 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-terra)와 설치 SDK를 확인해 설정했습니다. 본인 계정의 접근 가능 여부는 실제 연결 테스트에서 확인해야 합니다. 텍스트 요청 형식은 [공식 텍스트 안내](https://developers.openai.com/api/docs/guides/text)를 따릅니다. `store=false`는 abuse monitoring 등을 포함한 모든 원격 보관이 없다는 뜻이 아닙니다. [공식 데이터 제어](https://developers.openai.com/api/docs/guides/your-data).

HTTP 검사는 `httpx2.MockTransport`와 가짜 값만 사용했습니다. 400/401/403/404/429/503, 연결/시간 초과, 리다이렉트 거부, 크기/빈 응답/미지원 도구/거부 응답, 실제 키 반사·입력 탐지, 사용량 누락·기술 본문 보존, 외부 환경 라우팅 무시와 재시도 없음을 확인했습니다.

Qt 검사는 대기 중 이벤트/타이머 진행, 중복 방지, 10종 맥락 변경, 늦은 결과/종료·과거 답변 보존, 초기 저장 실패 시 HTTP 미시작·응답 저장 실패·취소 초안 보존, 키 조회 중 취소·오류 뒤 다음 초안 보존을 확인했습니다. 메모리 키 저장소와 별도 QA DB만 사용했습니다. Windows 키 보관의 네이티브 가짜 항목 검증은 [6A 기록](PHASE_6A_REPORT.md)을 유지하며 실제 키 읽기로 대신하지 않았습니다.

처음에는 전체 회귀의 두 SDK 통합 검사가 대기 시간 초과했습니다. 스택 검사로 `QTest.qWait` 대기 중 작업 스레드의 첫 SDK import가 실행 시간을 충분히 얻지 못함을 확인했습니다. 테스트 이벤트 펌프가 `time.sleep(0.005)`로 GIL을 양보하도록 수정했습니다. 차가운 SDK 로딩을 포함한 단독 두 검사도 통과했습니다. 앱의 `QApplication.exec()` 실행을 모방한 테스트 수정이며 네트워크 제한/검증 기준을 완화한 수정은 아닙니다.

화면 검사에서 두 줄로 바뀐 연결 상태의 토큰 줄이 잘리는 오류를 찾았습니다. `WrappedStatus`가 내용·너비·글꼴에 맞춰 최소 높이를 갱신하도록 수정했습니다. 기존 확인/취소/입력/보내기 Tab 순서와 연결 창 복귀 초점도 회귀로 확인했습니다. 배율 100/125/150/200%는 해당 Qt 프로세스에만 적용했으며 OS 설정을 변경하지 않았습니다. 앱 자체 위젯만 캡처했고 실제 OS 입력·IME·스크린리더 검증으로 간주하지 않습니다.

## 빌드와 남은 확인

SDK의 지연 로딩 Responses 리소스/타입을 PyInstaller hiddenimports에 추가했습니다. 고정 3종 팩 15파일·WAV 3종·모루/아이콘만 번들에 넣으며 원본 사진 27개·사용자 데이터·로그·키·QA는 제외했습니다. SDK 데이터가 추가되어 ZIP 파일 목록은 890개입니다. ZIP은 로컬 후보이며 게시하지 않았습니다.

최종 `Meonjakgwi-0.6.1-windows-x64.zip`: 84,716,364바이트, SHA-256 `af0562c744e58bfde5b95c83a71443a6f6f37076d030bc54d0b2f34e73947db8`. 재빌드하면 달라질 수 있으므로 함께 생성한 `.zip.sha256`과 비교합니다.

이 PC의 EXE 실행은 이전 Windows 앱 제어 차단 때문에 미검증이며 우회 실행/보안 설정 변경을 하지 않았습니다. 실제 API 인증/권한/모델·네트워크/TLS·청구액·실제 답변 품질·Win10/깨끗한 PC·IME/스크린리더·장치/절전/장시간은 [수동 검사](MANUAL_TESTS.md)에 남았습니다. 저장 후 키가 유효하다고 단정하지 않으며 Python/Qt 모든 메모리 사본 삭제나 같은 사용자 권한의 다른 프로그램 접근 차단을 보장하지 않습니다.

실행은 바탕화면 **먼작귀** 또는 `run_windows.bat`입니다. 새 소스 의존성은 `setup_windows.bat`으로 설치합니다. 연결 절차/취소/데이터 범위는 [온라인 안내](ONLINE_GUIDE.md)를 따릅니다. 다음 구현은 6C 제한된 작업 제안·검증·사용자 확인입니다.
