# PHASE 6A API 키 보관 — 0.6.0

검증일: 2026-11-10, 한국 시간. 후속 요청에 따라 키 보관 기능을 구현했습니다. **6A만 구현했으며 6B 연결 테스트/온라인 요청·6C AI 명령은 미구현**입니다. 실제 API 키·OpenAI 요청·사용자 DB는 테스트에 사용하지 않았습니다. DB 스키마는 6을 유지합니다.

## 구현

- `security/credentials.py`: ctypes의 Windows CredWriteW/CredReadW/CredDeleteW/CredFree, 사용자 Generic 항목·이 PC 로그인 간 유지·System32 DLL 검색. 읽기 크기/ASCII 입력 한도 검사, Windows 할당 메모리 해제·네이티브 임시 버퍼 정리. 평문 저장 대체 경로 없음.
- `services/api_key_service.py`: 입력 한도·상태 조회·저장·삭제·고정된 오류 문구, 키 본문 없는 변경 신호. 객체에 읽어 온 키를 캐시하지 않음.
- `ui/api_key_dialog.py`와 관리창: 설정의 실제 API 키 관리 버튼, Password 마스킹·민감한 입력 힌트, 입력/undo 비우기, 키 재표시 없음, 교체/삭제 확인 기본 No, 저장 여부와 연결 유효성 구분.
- 앱 구성과 채팅: 시작 시 자격 증명 API 호출 없음. 기본 항목 이름은 고정하고 별도 개발 데이터 폴더는 경로 해시로 격리. 변경 성공 때 대기 카드만 무효화하고 과거 답변·계획·타이머는 보존.

실제 온라인 모드·연결 테스트 버튼이나 비어 있는 기능은 추가하지 않았습니다. 새 HTTP/SDK 의존성도 없습니다. 사용법은 [키 관리 안내](API_KEY_GUIDE.md)를 따릅니다.

새 회귀는 `tests/test_credentials.py` 24개와 `tests/test_api_key_ui.py` 16개입니다. 입력 범위·저장 오류·키 없는 상태 신호·네이티브 읽기 한도/해제/버퍼 정리·누락과 접근 오류 구분·비Windows 실패·마스킹/접근성 값·undo·닫기/숨기기·교체/삭제 확인·실패 시 카드 유지·성공 시 무효화·계획/타이머 보존·개발 항목 격리·시작 시 지연 로딩을 검사했습니다.

마지막 검토에서 비정상적인 기존 항목도 교체/삭제할 수 있도록 존재 여부와 본문 유효성 검사를 분리했습니다. 빈 값·짧은 값·과도한 길이·잘못된 ASCII에 대한 회귀를 추가했습니다. 최종 전체 회귀는 서로 다른 임시 폴더의 두 파일 묶음으로 실행해 합산했으며, Windows Qt 관련 40개도 다시 확인했습니다.

GUI 회귀의 가짜 canary가 설정 JSON·SQLite 덤프와 DB/로그 파일·화면 상태 문구에 없는지 확인했습니다. 입력은 Password로 표시하며 Qt 접근성 값도 원문과 다름을 검사했습니다. 앱의 변경 신호는 인수가 없습니다. 모든 비밀 문자열이나 운영체제 메모리 덤프까지 완벽하게 검사했다고 해석하지 않습니다.

### 실제 Windows 저장 검사

`tools/credential_smoke.py`는 기존 항목을 열거하지 않고 `DesktopBuddy/QA/<UUID>/OpenAI/APIKey` 하나만 사용합니다. 만약 그 이름이 이미 있으면 덮어쓰거나 삭제하지 않습니다. 가짜 값은 출력/JSON에 넣지 않으며 생성한 항목을 finally에서 정리합니다.

제한된 실행 세션에서는 처음 두 번의 저장이 오류 **1312**로 실패했습니다. 두 QA 항목 모두 부재를 확인했습니다. 고유 QA 스크립트를 제한 밖의 승인된 실행으로 두 번 확인했을 때 저장·읽기 일치·교체 일치·삭제 후 부재가 모두 True였고 종료 코드는 0이었습니다. 해당 QA 항목도 모두 삭제했습니다. 실제 키나 기본 앱 항목은 읽지 않았고 네트워크 요청은 없었습니다. 제한된 로그인 세션에서 실패할 수 있다는 [Microsoft API 문서](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credwritew)와 구분해 기록합니다.

### 화면과 패키지

`tools/ui_smoke.py`는 메모리 전용 QA 저장소로 키 창의 빈 입력·가짜 마스킹 입력·저장 후·저장소 오류를 밝음/어둠에서 추가 검사합니다. 기존 31개에 8개가 추가돼 조건마다 39개입니다. `.qa/ui-audit-key060-100`, `-125`, `-150`, `-200`에 실제 DPR과 보고서를 기록했습니다. 요청 관리창은 560×360, 키 대화상자는 별도 크기로 보정합니다. 배율은 프로세스에만 적용했고 실제 장치 전환은 수행하지 않았습니다.

마스킹된 밝은 화면과 오류 상태의 어두운 화면을 직접 확인했습니다. 키 입력은 가짜 값이며 사용자 화면/키를 캡처하지 않았습니다.

이번 ZIP은 73,586,799바이트, SHA-256은 다음과 같습니다. 재생성 시 값이 달라질 수 있습니다.

```text
99f502c2baedc780d87fe52f7c4e2693daa3d9a3d300d6ed2b8f021cfdf9ea42
```

새 보안/서비스/대화상자 모듈은 번들에 포함하고 테스트·QA 실행기·사용자 DB/로그·작업 사진 원본은 포함하지 않습니다. 생성/검증 방법은 [배포 후보 안내](RELEASE_GUIDE.md)를 따릅니다.

## 남은 확인과 다음 단계

실제 키의 인증·모델 지원·온라인 오류/시간 초과·취소·요금·사용량은 6B, 모델 도구 제안과 확인 후 실행은 6C에 남습니다. 실제 Windows IME·스크린리더·음악 청취·절전/모니터 전환·Windows 10·깨끗한 PC EXE도 미검증입니다. [수동 목록](MANUAL_TESTS.md)을 따릅니다.

저장 보장은 같은 Windows 계정의 악성 프로그램 접근 방지까지 포함하지 않으며 Python/Qt 모든 메모리 사본의 완전한 삭제를 보장하지 않습니다. 본인 키 보관만 제공하며 개발자 공용 키를 앱에 넣지 않습니다. [OpenAI 공식 인증 안내](https://developers.openai.com/api/reference/overview#authentication), [Windows 자격 증명 계약](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw)을 확인했습니다.
