# 캐릭터 이미지 준비 안내

개발자가 캐릭터 자료를 앱에 포함하고 사용자는 제공 목록에서 선택하는 방식입니다. 초기 목표는 치이카와·하치와레·우사기입니다. 새 캐릭터는 앱 업데이트로 추가합니다.

현재 실제로 연결된 캐릭터는 모루뿐이며 idle/happy 반응을 사용합니다. 세 캐릭터 선택과 집중·휴식·공부 공백에 따른 자동 상태 전환은 아직 구현하지 않았습니다. 아래 폴더는 원래 명세에 맞춘 자료 준비 위치입니다. 폴더에 파일을 넣는 것만으로 실행 중인 앱이 변경되지는 않습니다.

## 1. 준비 형식

- **투명 배경 PNG(RGBA)**를 권장합니다. 흰색 배경이나 체크무늬가 그림으로 들어간 이미지는 실제 투명 이미지가 아닙니다.
- **512×512 픽셀 권장**입니다. 1024×1024도 준비 자료로 받을 수 있으며 512×512는 강제 조건이 아닙니다. 작은 화면에서 읽히도록 얼굴과 실루엣을 단순하고 선명하게 준비합니다.
- 한 파일에는 **한 캐릭터의 한 프레임**만 넣습니다. 여러 표정이나 세 캐릭터를 한 장에 모은 시트보다 프레임별 파일이 바로 연결하기 좋습니다.
- 캐릭터별 프레임의 캔버스 크기·기준 위치·그림 배율을 통일합니다. 의도한 점프나 움직임 외에 크기/위치가 흔들리지 않게 하고 귀·손·발·소품이 잘리지 않도록 여백을 둡니다.
- 캐릭터 주변의 여백은 대략 5~10%부터 잡고 가장 큰 동작도 캔버스 안에 들어가게 합니다. 의상·선 두께·색감은 프레임 사이에 일관되게 유지합니다.
- 말풍선 문장, 타이머 숫자, 앱 버튼은 그림에 넣지 않습니다. 앱에서 따로 표시합니다. 집중 상태의 책이나 연필 같은 동작 소품은 그림에 포함할 수 있습니다.
- 파일명은 상태별로 `frame_001.png`, `frame_002.png` 순서입니다. 각 상태에서 001부터 다시 시작합니다.
- JPG·스크린샷은 배경 정리 등이 필요할 수 있습니다. GIF/APNG, 동영상, 한 장에 여러 컷인 스프라이트 시트는 현재 프레임 재생기에 그대로 연결하는 형식이 아니며 PNG 프레임으로 정리하는 과정이 필요합니다.

## 2. 상태별 그림 — 세 캐릭터 각각 준비

아래 프레임 수는 **서로 조금씩 다른 그림의 권장 개수**이며 필수 최소 개수가 아닙니다. 모든 상태는 한 장의 정지 이미지로도 시작할 수 있습니다.

| 폴더 | 전환 상황/예정 역할 | 그려 둘 표정·동작 예시 | 움직임용 권장 프레임 |
|---|---|---|---|
| `idle` | 평소 대기 | 편하게 서 있기, 살짝 숨쉬기·몸 흔들기 | 4~8장 |
| `blink` | 대기 중 간헐적 눈 깜빡임 | 눈 뜸 → 감음 → 다시 뜸 | 2~3장 |
| `happy` | 클릭 인사, 짧은 긍정 반응 | 웃기, 손 흔들기, 가볍게 반기기 | 4~8장 |
| `excited` | 더 큰 기쁨 반응 | 팔 들기, 신나게 폴짝 뛰기 | 6~10장 |
| `surprised` | 사용자가 유발한 특별 반응 | 눈이 커짐, 살짝 움찔하기 | 2~4장 |
| `sleepy` | 수면 상태 전환 전 | 눈이 반쯤 감김, 하품하기 | 2~4장 |
| `sleep` | 수면 시간대/수면 상태 | 눈 감고 잠들기, 느린 숨쉬기 | 2~4장 |
| `focus` | 집중 타이머가 진행 중일 때 | 책 읽기, 필기하기, 집중한 표정 | 2~6장 |
| `break` | 휴식 타이머가 진행 중일 때 | 편안한 표정, 기지개·가볍게 쉬기 | 2~6장 |
| `sad` | 설정한 유효 공부 공백 조건 충족 | 고개 살짝 숙이기, 시무룩한 표정 | 2~4장 |
| `thinking` | 채팅 답변을 준비할 때 | 고개 갸웃, 고민하는 표정 | 2~6장 |
| `talking` | 채팅 응답을 보여줄 때 | 입 모양이 조금씩 바뀜, 작은 손짓 | 3~6장 |
| `complete` | 집중/할 일을 완료했을 때 | 환하게 웃기, 박수·짧은 축하 | 4~8장 |

surprised/excited의 구체적인 자동 발동 조건은 후속 상태 관리 기능을 구현할 때 확정합니다. 알림마다 과도하게 놀라거나 뛰도록 만들지 않습니다.

공부 공백 sad는 원래 명세의 기본 3일 기준, 기본 15분 이상 실제 집중을 완료한 유효 기록, 최초 사용자/휴식일/설정 해제 예외를 반영하는 예정 기능입니다. 단순히 앱을 실행하지 않았다는 이유로 슬픔을 적용하지 않습니다. 현재 이 판단 기능은 구현하지 않았습니다.

## 3. 우선순위와 최소 준비량

먼저 캐릭터별로 **idle, happy, focus, break, complete, sad, sleep** 7가지 표정을 한 장씩 준비하면 됩니다. 세 캐릭터 합계 21개 상태 파일입니다. happy와 complete를 같은 그림으로 시작하는 등 재사용도 가능하며, 별도 새 그림을 반드시 21장 그려야 한다는 뜻은 아닙니다.

그다음 idle의 숨쉬기/눈 깜빡임과 happy의 짧은 반응부터 연속 프레임을 추가합니다. blink는 idle 애니메이션 안에 포함할 수도 있습니다. sleepy/excited/surprised/thinking/talking은 이후에 채워도 됩니다. 비어 있는 상태는 기본 표정으로 대체하는 방향으로 연결합니다.

**정지 이미지 한 장이 자동으로 여러 동작 그림이 되는 것은 아닙니다.**

- 상태마다 1장씩: 상황에 따라 표정이 바뀌는 캐릭터.
- 상태마다 연속 프레임 여러 장: 같은 상황 안에서도 움직이는 캐릭터.
- 완전히 같은 그림을 여러 장 복사: 동작 변화가 생기지 않음.

예를 들어 happy 4장은 '미소 → 손을 조금 들기 → 손을 흔들기 → 원래 자세'처럼 자연스럽게 이어지도록 준비합니다. 반복 동작은 마지막 그림과 첫 그림의 자세를 가깝게 만들면 튐이 줄어듭니다. 재생 속도·반복 여부·종료 후 복귀·상태 우선순위는 앱과 manifest에서 설정하므로 사진에 시간을 적을 필요는 없습니다.

## 4. 넣을 위치와 첨부 방법

캐릭터 ID는 `chiikawa`(치이카와), `hachiware`(하치와레), `usagi`(우사기)입니다. 상태 폴더 안에 PNG를 넣습니다.

예: `chiikawa/focus/frame_001.png`, `hachiware/sad/frame_001.png`, `usagi/happy/frame_001.png`.

프로젝트의 세 캐릭터 각각에 13개 상태 폴더를 준비했습니다. `.gitkeep`은 Git에서 빈 폴더를 유지하는 파일이므로 그대로 두어도 됩니다. `manifest.json`이나 Python 코드를 직접 편집할 필요는 없습니다.

채팅으로 제공할 때에는 PNG를 상태 이름과 함께 첨부하거나, **폴더 구조를 유지한 ZIP**으로 묶어 첨부하면 됩니다. PNG 한 장씩이면 '치이카와/집중', '우사기/슬픔'처럼 캐릭터와 상황을 함께 적습니다. ZIP은 개발 자료 전달용이며 앱 사용자가 ZIP을 직접 가져오는 기능은 현재 없습니다.

캐릭터 선택 미리보기는 idle의 첫 그림을 활용할 수 있어 별도 썸네일은 당장 준비하지 않아도 됩니다. 그림을 받은 뒤 투명도·크기·정렬·순서를 확인하고 목록과 재생 manifest를 연결합니다.

공개 저장소와 배포본에는 사용 허락이 확인된 자료만 포함합니다. 현재 자료 폴더에는 실제 캐릭터 이미지가 없습니다.
